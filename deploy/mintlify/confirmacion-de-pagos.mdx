Padi permite consultar los pagos recibidos por tu comercio desde el servidor. Confirmá el cobro usando estas consultas antes de entregar el pedido o activar un servicio.

## Encontrar el pago

Consultá los cobros recientes con la API Key:

```bash
curl --fail-with-body   "$WALLET_API_URL/api/v1/integrations/received-payments?limit=20"   --header "X-Api-Key: $WALLET_MERCHANT_API_KEY"
```

La respuesta `200 OK` es una lista de pagos. Buscá el que tenga `paymentLinkId` igual al `id` del enlace guardado con tu pedido. Cada pago tiene su propio `id`, diferente del identificador del enlace.

El parámetro `limit` vale 20 por defecto. Este listado no expone un cursor de paginación: no lo trates como un historial completo de conciliación.

## Verificar un pago identificado

Definí `PAYMENT_ID` con el `id` del pago:

```bash
curl --fail-with-body   "$WALLET_API_URL/api/v1/integrations/received-payments/$PAYMENT_ID"   --header "X-Api-Key: $WALLET_MERCHANT_API_KEY"
```

Antes de marcar el pedido como pagado, comprobá:

1. Que `paymentLinkId` coincida con el enlace del pedido.
2. Que `amount` y `currency` coincidan con el importe esperado.
3. Que `status` sea `Succeeded`.

Guardá el `id` del pago y actualizá el pedido de forma que procesar dos veces el mismo pago no duplique la entrega.

<Warning>
La consulta de cobros del comercio usa `Succeeded` para un pago exitoso. El comprobante del checkout usa `Completed`. Para conciliar desde tu servidor, verificá `Succeeded` en `received-payments`.
</Warning>

El regreso del comprador, una captura del comprobante o un parámetro recibido en tu frontend no confirman el cobro por sí solos.

## Consultar el enlace

Para recuperar el enlace de tu comercio, definí `PAYMENT_LINK_ID` con su `id`:

```bash
curl --fail-with-body   "$WALLET_API_URL/api/v1/integrations/payment-links/$PAYMENT_LINK_ID"   --header "X-Api-Key: $WALLET_MERCHANT_API_KEY"
```

El estado del enlace y el estado del pago son recursos distintos. Un enlace de uso múltiple puede recibir varios pagos; confirmá cada uno por su identificador.

## Notificaciones webhook

El backend dispone de operaciones para guardar y desactivar la configuración de un webhook. En el código revisado de `develop` no se encontró el envío de eventos, un contrato de notificación, firma ni política de reintentos. Esta versión de la guía utiliza consultas a la API para confirmar los cobros; configurar una URL no garantiza recibir notificaciones.

## Errores de consulta

| Respuesta | Interpretación | Acción |
| --- | --- | --- |
| `401` | La solicitud no está autenticada con una API Key válida. | Revisá la credencial enviada por el servidor. |
| `404` con `PAYMENT_NOT_FOUND` | El pago no existe o no pertenece al comercio. | Revisá el identificador y la API Key. |
| `404` con `PAYMENT_INTENT_NOT_FOUND` | El enlace no existe o no pertenece al comercio. | Usá el `id` guardado al crearlo. |

Un timeout o un error del servicio deja la confirmación pendiente. No lo interpretes como un cobro exitoso.
