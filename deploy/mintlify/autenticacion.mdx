Padi identifica a tu aplicación externa mediante una API Key. Primero registrá el comercio; después enviá esa credencial en el encabezado `X-Api-Key` al crear enlaces de pago y consultar los cobros recibidos.

## Si ya creaste un vendedor en la app

El registro de tipo **Vendedor** de [la aplicación Padi](https://padi-billetera.netlify.app/) crea una cuenta de usuario para operar desde la interfaz. No entrega una API Key. Para cobrar manualmente, seguí [Crear un link desde la app](/cobrar-desde-app).

El alta que sigue corresponde a una aplicación externa que se identifica como comercio mediante `X-Api-Key`. No se obtiene esa credencial desde la pantalla **Cobros y Ventas**.

## Registrar el comercio

El alta no requiere una credencial previa:

```bash
export WALLET_API_URL="https://padi.runasp.net"

curl --fail-with-body --request POST   "$WALLET_API_URL/api/v1/integrations/register"   --header "Content-Type: application/json"   --data '{
    "companyName": "Tienda de ejemplo",
    "contactEmail": "integraciones@example.com",
    "description": "Cobros de pedidos de la tienda"
  }'
```

| Campo | Requerido | Descripción |
| --- | --- | --- |
| `companyName` | Sí | Nombre del comercio, hasta 150 caracteres. |
| `contactEmail` | Sí | Correo de contacto válido, hasta 254 caracteres. |
| `description` | No | Descripción de la integración, hasta 500 caracteres. |
| `cuit` | No | CUIT del comercio. |

La respuesta `201 Created` incluye `id`, `companyName`, `contactEmail`, `description`, `apiKey`, `walletId`, `createdAt`, `cuit` y `webhookUrl`. El alta crea también la billetera del comercio.

<Warning>
La API Key se entrega en texto plano una única vez durante el alta. Guardala en el almacenamiento seguro de tu servidor. No la incluyas en el frontend, repositorios, URLs ni registros de solicitudes.
</Warning>

## Usar la credencial

Definí `WALLET_MERCHANT_API_KEY` en el entorno de tu servidor con el valor recibido en `apiKey`. Podés verificar el acceso consultando el perfil:

```bash
curl --fail-with-body   "$WALLET_API_URL/api/v1/integrations/profile"   --header "X-Api-Key: $WALLET_MERCHANT_API_KEY"
```

La respuesta `200 OK` contiene los datos del comercio. Una credencial ausente o inválida impide el acceso a las operaciones protegidas y devuelve `401 Unauthorized`.

## Credenciales del comprador

Para generar el enlace no necesitás iniciar sesión como comprador. La API Key identifica al comercio. Cuando el comprador paga con saldo de su billetera o con una tarjeta asociada, el checkout gestiona su autenticación de usuario.

Continuá con [Cobros y checkout](/cobros).
