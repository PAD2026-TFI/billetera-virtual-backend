Para cobrar un pedido con Padi, creá un enlace desde tu servidor usando la [API Key del comercio](/autenticacion). Guardá su identificador junto al pedido y compartí la URL de checkout con el comprador.

Si querés generar el cobro manualmente desde Netlify, seguí [Crear un link desde la app](/cobrar-desde-app). Esta página describe la operación desde el servidor de una aplicación externa.

## Crear el enlace

```bash
curl --fail-with-body --request POST   "$WALLET_API_URL/api/v1/integrations/payment-links"   --header "X-Api-Key: $WALLET_MERCHANT_API_KEY"   --header "Content-Type: application/json"   --data '{
    "title": "Pedido 1042",
    "description": "Compra en Tienda de ejemplo",
    "amount": 1500,
    "currency": "ARS",
    "type": "SingleUse",
    "ttlMinutes": 30
  }'
```

| Campo | Requerido | Uso |
| --- | --- | --- |
| `amount` | Sí | Importe mayor que cero. `1500` representa 1500 pesos. |
| `title` | Sí | Concepto visible para el comprador. |
| `description` | No | Detalle del pedido. |
| `currency` | No | Usá `ARS`, la moneda de los cobros actuales. |
| `type` | No | `SingleUse` para un solo cobro; `MultiUse` para varios. Por defecto, `SingleUse`. |
| `ttlMinutes` | No | Minutos de vigencia. Si se omite, no se establece vencimiento por TTL. |

La respuesta `201 Created` contiene:

| Campo | Uso en tu integración |
| --- | --- |
| `id` | Guardalo como identificador del enlace asociado al pedido. |
| `token` | Permite consultar los detalles públicos del enlace. |
| `amount`, `currency` | Verificá que correspondan al pedido. |
| `title`, `description` | Concepto del cobro. |
| `status`, `type` | Estado y modalidad del enlace. |
| `createdAt`, `expiresAt` | Fechas de creación y vencimiento; `expiresAt` puede ser nulo. |
| `checkoutUrl` | Dirección a la que enviás al comprador. |
| `qrCodeUrl` | Dirección de la imagen QR del checkout. |

La billetera destinataria se obtiene del comercio autenticado. Esta operación no recibe un identificador externo de pedido: conservá la relación entre el pedido de tu sistema y el `id` del enlace.

## Abrir el checkout

Redirigí al comprador a `checkoutUrl` o mostrá el QR de `qrCodeUrl`. Usá las URLs recibidas, sin reconstruirlas a partir del dominio de la aplicación.

Podés consultar los detalles públicos sin API Key:

```bash
curl --fail-with-body   "$WALLET_API_URL/api/v1/public/payment-links/$PAYMENT_LINK_TOKEN"
```

Definí `PAYMENT_LINK_TOKEN` con el `token` devuelto al crear el enlace. La respuesta incluye `isPayable`: si es `false`, el enlace no admite un pago en ese momento. El QR se obtiene en `GET /api/v1/public/payment-links/{token}/qr` y devuelve `image/svg+xml`.

## Evitar enlaces duplicados

La creación del enlace no implementa deduplicación mediante `Idempotency-Key`. Guardá la respuesta antes de volver a crear un enlace para el mismo pedido. Si una solicitud termina en timeout, tu aplicación debe tratar el resultado como incierto y evitar un reintento automático que genere otro enlace.

Después de abrir el checkout, seguí [Confirmación de pagos](/confirmacion-de-pagos) para verificar el resultado desde tu servidor.
